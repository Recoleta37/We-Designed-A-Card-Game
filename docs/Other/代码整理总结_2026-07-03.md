# 代码整理总结

> 日期: 2026-07-03

## 动机

`MainWindow.cpp` 原本 1591 行，UI 构建、战斗结算、剧情播放、地图动画全部耦合在同一个类里，修改任意功能都需要在近 1600 行中定位，容易引入 bug。

## 做了什么

将 MainWindow 拆分出 4 个独立模块，各司其职：

```
MainWindow (680 行)          ← UI 构建 + 跨系统编排
 ├── StoryManager (300 行)   ← 剧情加载 / 打字机播放 / JSON 解析
 ├── MapManager  (520 行)    ← 章节标题动画 / 世界地图 overlay
 ├── BattleEngine (1,230 行) ← 单位创建 / 战斗结算 / 技能 / 遗物
 └── GameTypes.h (143 行)    ← 共享常量 + 数据结构 + 章节配置
```

## 文件清单

| 文件 | 说明 |
|------|------|
| `GameTypes.h` | 游戏常量 (`kHeroSlot`, `kMaxSkills`, …)、`UnitTemplate` / `UnitInstance` / `ChapterDef` 等结构体、`chapters()` 全部章节数据 |
| `StoryManager.h/.cpp` | `loadStory()` 解析 `data/story.json`；`showStory()` / `showStoryKey()` 按 key 顺序播放剧情；打字机逐字效果；`hasScene()` 查询场景是否存在 |
| `MapManager.h/.cpp` | `showChapterTitle()` 章节标题淡入动画；`showMapPoint()` 地图坐标点亮；`mapPointForChapter()` 章节→坐标映射；`resetMapPoints()` |
| `BattleEngine.h/.cpp` | 全部战斗逻辑：单位创建与棋盘管理、伤害/治疗/攻击结算、Boss 特殊机制、技能生成与释放、遗物效果与融合、战斗流程（关卡初始化/回合结算/死亡清理/结局） |
| `MainWindow.h/.cpp` | 仅保留 UI 构建（`buildUi` / `buildBoard` / `buildBottomBar` / `buildRightPanel`）、跨系统编排（`initData` / `startGame` / `enterCurrentLevel` / `advanceLevel`）、UI 刷新（`refreshUi` 族、`appendLog`）、`castSelectedSkills`（需读 UI 控件状态） |

## 关键设计决策

1. **`chapterIndex` / `levelIndex` 留在 MainWindow**。这两个变量被跨系统编排方法修改（`advanceLevel`、`enterCurrentLevel`），BattleEngine 通过参数接收，避免双写不同步。

2. **BattleEngine 用回调而非 signal/slot** 与 MainWindow 通信（`refreshCallback`、`restartGameCallback`），与 StoryManager / MapManager 的风格一致。

3. **`[Recoleta37]` 标注** 所有新增和修改的代码块，方便追溯。

## 期间修了的 Bug

- **技能释放上限**: 新增 `skillsUsedThisTurn` 计数器，释放和 UI 勾选均限制每回合最多 2 次
- **遗物替换对话框无退出**: 添加「不替换」选项
